### Hypothesis Statement

**Primary Hypothesis:** Node.js servers running vulnerable React Server Components (versions 19.0.0, 19.1.0, 19.1.1, 19.2.0) may be compromised by China-nexus threat actors exploiting CVE-2025-55182 (CWE-502: Unsafe Deserialization). Due to absence of HTTP request logs, we cannot detect initial exploitation at the HTTP layer but can detect:

1. **Vulnerability Inventory (Part A):** Presence of vulnerable React installations through npm package management artifacts in process telemetry
2. **Post-Exploitation Behaviors (Part B):** Node.js processes spawning shells, credential access tools, network enumeration, or persistence mechanisms indicating successful RCE follow-on activity

**Rationale:** With process telemetry as the sole data source, we cannot observe the malicious HTTP POST to Server Function endpoints but can detect subsequent attacker actions after code execution is achieved.

**Key Challenge:** CVE-2025-55182 is fundamentally a web application layer vulnerability (pre-auth RCE via unsafe deserialization), but our hunt vault only has endpoint/process telemetry. We have **zero visibility into HTTP request logs, web application logs, or network packet captures**. This means:
- ✅ **We CAN detect**: Post-RCE behaviors (shell spawning, credential theft, persistence, C2, lateral movement)
- ❌ **We CANNOT detect**: The initial HTTP exploitation payload, deserialization attack, or Server Function endpoint abuse

**Hunt Strategy:** Focus on observable post-exploitation TTPs to identify compromised hosts even though we missed the initial compromise vector.

```sql
SELECT timestamp, host_name, user_name, process_name,
       process_command_line, process_parent_name
FROM nocsf_unified_events

  AND process_name IN ('npm', 'yarn', 'pnpm')
  AND (process_command_line ILIKE '%react-server-dom-webpack%'
```

```sql
           AND process_command_line NOT ILIKE '%kubectl%' THEN 'lateral_movement'
      WHEN (process_command_line ILIKE '%crontab%' OR process_command_line ILIKE '%authorized_keys%')
           AND process_command_line NOT ILIKE '%-l%' THEN 'persistence'

    COUNT(*) as total_events

  GROUP BY host_name, user_name
  HAVING COUNT(DISTINCT ttp_category) >= 3
    AND (MAX(timestamp) - MIN(timestamp)) <= INTERVAL 1 HOUR
)
SELECT

    cb.user_name,

    cb.last_event,

    cb.ttp_chain,

    EXTRACT(EPOCH FROM (cb.last_event - cb.first_event)) as time_window_seconds
FROM chained_behaviors cb
ORDER BY cb.distinct_ttps DESC, cb.first_event DESC
LIMIT 100;
```

### BHD-6: Suspicious Discovery Pattern Analysis (MEDIUM)

**Objective:** Detect manual system enumeration patterns characteristic of human attackers vs automated tooling.

**Behavior Focus:** Rapid sequential execution of discovery commands (whoami; id; hostname; uname pattern).

**Production-Tuned Query:**
```sql
WITH discovery_events AS (
  SELECT
    timestamp,
    host_name,
    user_name,
    process_name,
    process_command_line,
    LAG(timestamp) OVER (PARTITION BY host_name, user_name ORDER BY timestamp) as prev_timestamp,
    LAG(process_name) OVER (PARTITION BY host_name, user_name ORDER BY timestamp) as prev_command,
    EXTRACT(EPOCH FROM (timestamp - LAG(timestamp) OVER (PARTITION BY host_name, user_name ORDER BY timestamp))) as seconds_since_last
  FROM nocsf_unified_events
  WHERE ingest_time >= now() - INTERVAL 1 HOUR
    AND process_parent_name = 'node'
    AND process_name IN ('whoami', 'id', 'hostname', 'ifconfig', 'netstat', 'ss', 'w', 'last')
    AND process_command_line NOT ILIKE '%-A -o ppid%'
    AND process_command_line NOT ILIKE '%-o ppid=%'
    AND process_command_line NOT ILIKE '%-o command=%'
    AND process_command_line NOT ILIKE '%uname -sr%'
    AND process_command_line NOT ILIKE '%netstat -rn%'
    AND process_command_line NOT ILIKE '%ip -%r%'
    AND user_name NOT ILIKE '%jenkins%'
    AND user_name NOT ILIKE '%gitlab%'
    AND user_name NOT ILIKE '%criblbuild%'
    AND user_name NOT IN ('root', '')
),
rapid_sequences AS (
  SELECT
    host_name,
    user_name,
    COUNT(*) as discovery_commands,
    COUNT(DISTINCT process_name) as unique_commands,
    string_agg(process_name, ' -> ' ORDER BY timestamp) as command_sequence,
    AVG(seconds_since_last) as avg_time_between_commands,
    MIN(timestamp) as first_discovery,
    MAX(timestamp) as last_discovery,
    EXTRACT(EPOCH FROM (MAX(timestamp) - MIN(timestamp))) as total_duration_seconds
  FROM discovery_events
  WHERE seconds_since_last < 5
  GROUP BY host_name, user_name
  HAVING COUNT(*) >= 3
    AND COUNT(DISTINCT process_name) >= 2
    AND EXTRACT(EPOCH FROM (MAX(timestamp) - MIN(timestamp))) < 30
)
SELECT
  host_name,
  user_name,
  discovery_commands,
  unique_commands,
  command_sequence,
  ROUND(avg_time_between_commands::numeric, 2) as avg_seconds_between,
  first_discovery,
  last_discovery,
  total_duration_seconds
FROM rapid_sequences
ORDER BY discovery_commands DESC, total_duration_seconds ASC
LIMIT 100;
```

## LEARN: Prepare the Hunt

### Hypothesis Statement

**Primary Hypothesis:** Servers running vulnerable HPE OneView infrastructure management software (versions prior to 11.00) may be compromised by remote unauthenticated threat actors exploiting CVE-2025-37164 (CVSS 10.0: Unauthenticated Remote Code Execution). Due to absence of HTTP request logs and network flow data, we cannot detect initial exploitation at the web application layer but can detect:

1. **Vulnerability Inventory (Part A):** Presence of HPE OneView installations through process telemetry showing OneView service processes, installation artifacts, or management operations
2. **Post-Exploitation Behaviors (Part B):** HPE OneView processes spawning unexpected shells, credential access tools, network enumeration, or persistence mechanisms indicating successful RCE follow-on activity

**Rationale:** With process telemetry as the sole data source, we cannot observe the malicious HTTP request exploiting the unauthenticated RCE vulnerability but can detect subsequent attacker actions after code execution is achieved on the HPE OneView server.

**Key Challenge:** CVE-2025-37164 is fundamentally a web application layer vulnerability (CWE-94 code injection via unauthenticated REST API endpoint `/rest/id-pools/executeCommand`), but our hunt vault only has endpoint/process telemetry. We have **zero visibility into HTTP request logs, web application logs, or network packet captures**. This means:
- ✅ **We CAN detect**: Post-RCE behaviors (shell spawning, credential theft, persistence, C2, lateral movement, infrastructure enumeration)
- ❌ **We CANNOT detect**: The initial HTTP POST to `/rest/id-pools/executeCommand` or the injected command payload
- ⚠️ **Coverage Concern**: HPE OneView is enterprise infrastructure management software - deployment may be limited across our customer base (primarily developer workstation environments)
- 🚨 **Critical Impact**: OneView compromise = entire infrastructure compromise (VMware vCenter, HPE 3PAR storage, HPE iLO access)

**Hunt Strategy:** Focus on observable post-exploitation TTPs to identify compromised HPE OneView servers even though we missed the initial compromise vector.

### Threat Context

**CVE-2025-37164 Overview:**
- **Vulnerability Type:** Remote Code Execution (RCE) via Code Injection
- **CWE Classification:** CWE-94 (Improper Control of Generation of Code)
- **Authentication Required:** None (unauthenticated access)
- **Attack Complexity:** Low (CVSS 10.0 indicates maximum exploitability)
- **Affected Software:** HPE OneView (IT infrastructure management platform)
- **Affected Versions:** All versions 5.20 through 10.20 (pre-11.0)
- **Fixed Version:** HPE OneView 11.00 or later
- **Additional Mitigation:** Hotfix HPE_OV_CVE_37164_Z7550-98077 available for 5.20-10.20
- **Public Disclosure:** December 16, 2025
- **Last Modified:** December 18, 2025
- **Discoverer:** Nguyen Quoc Khanh (brocked200) - Vietnamese security researcher
- **Active Exploitation:** Expected imminent (described as "so simple" by security researchers)

**Technical Vulnerability Details:**
- **Vulnerable Endpoint:** `/rest/id-pools/executeCommand`
- **Attack Vector:** HTTP POST to unauthenticated REST API endpoint
- **Exploitation Method:** Command injection via `executeCommand` API call
- **Introduced:** Circa 2020 (4-5 years of exposure window)
- **Security Researcher Assessment:** Kevin Beaumont described this as feeling "like a vulndoor" - REST command requiring no authentication to execute arbitrary commands
- **Detection via Shodan:** `product:"HPE OneView"` (for identifying exposed instances)
- **Hotfix Mitigation:** HPE's patch blocks HTTP access to `/rest/id-pools/executeCommand` endpoint via webserver rules

**CVSS v3.1 Vector Breakdown:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H`
- **Attack Vector (AV:N):** Network - remotely exploitable
- **Attack Complexity (AC:L):** Low - no special conditions required
- **Privileges Required (PR:N):** None - no authentication needed
- **User Interaction (UI:N):** None - fully autonomous exploitation
- **Scope (S:C):** Changed - impact extends beyond vulnerable component (infrastructure-wide)
- **Confidentiality Impact (C:H):** High - complete information disclosure
- **Integrity Impact (I:H):** High - complete data manipulation capability
- **Availability Impact (A:H):** High - complete denial of service capability

**HPE OneView Context:**
- **Purpose:** Centralized IT infrastructure management platform for HPE servers, storage, and networking
- **Typical Deployment:** Data centers, enterprise server environments, virtualized infrastructure
- **Access Profile:** Web-based management interface (HTTPS), typically internal network access
- **Privileged Access:** OneView has administrative access to managed infrastructure (high-value target)
- **Attack Surface:** Web application endpoints, API interfaces, management console
- **Infrastructure Access (CRITICAL):** OneView "allows attacker to access VMware, 3PAR storage etc by design" (Kevin Beaumont)
  - **VMware vCenter/ESXi:** Full hypervisor management credentials and access
  - **HPE 3PAR Storage Arrays:** Storage management credentials and data access
  - **HPE iLO (Integrated Lights-Out):** Out-of-band management for physical servers
  - **Firmware Management:** Control over server firmware, BIOS, and lifecycle management
  - **Network Infrastructure:** Managed switches, network configuration access

**Attack Scenario (Enhanced with Infrastructure Targeting):**
1. **Initial Access:** Attacker identifies externally accessible HPE OneView instance (port scan, Shodan: `product:"HPE OneView"`)
2. **Exploitation:** Attacker sends HTTP POST to `/rest/id-pools/executeCommand` with command injection payload (no authentication required)
3. **Code Execution:** Remote code execution achieved in context of HPE OneView service process (SYSTEM/root privileges)
4. **Infrastructure Credential Harvesting:** Attacker accesses OneView credential database containing:
   - VMware vCenter administrator credentials
   - HPE 3PAR storage admin passwords
   - HPE iLO administrative credentials
   - SSH keys for managed servers
5. **Infrastructure-Wide Compromise:** Attacker pivots from OneView to:
   - VMware ESXi hosts (via stolen vCenter credentials)
   - 3PAR storage arrays (data exfiltration, ransomware staging)
   - Physical servers (via iLO out-of-band management)
   - Firmware manipulation (persistence, backdoors)
6. **Domain-Wide Impact:** Complete enterprise infrastructure compromise from single vulnerable OneView instance

### Query Templates

#### Query 1: HPE OneView Discovery (Count-First)

**Purpose:** Identify customer environments with HPE OneView installations

```sql
-- HPE OneView Discovery Query (Count-First)
-- Purpose: Identify customers with HPE OneView deployments
-- Expected: 0-10 organizations (specialized software)
-- Bound: 30-day window, COUNT only

SELECT
    nebulock_organization_id,
    COUNT(DISTINCT endpoint.name) as oneview_host_count,
    COUNT(*) as event_count
FROM nocsf_unified_events
WHERE
    time >= now() - INTERVAL 30 DAY
    AND (
        -- Linux OneView processes
        process.file.name IN ('hpe-oneview', 'oneview-service', 'oneview-appliance')
        OR process.file.path LIKE '%/opt/hpe/oneview/%'
        OR process.file.path LIKE '%/var/lib/hpe/oneview/%'
        -- Windows OneView processes
        OR process.file.name = 'HPEOneView.exe'
        OR process.file.path LIKE '%Hewlett Packard Enterprise\\OneView%'
        -- Java processes with OneView in command line
        OR (process.file.name = 'java' AND process.cmd_line LIKE '%com.hp.ov%')
        OR (process.file.name = 'java.exe' AND process.cmd_line LIKE '%oneview%')
    )
GROUP BY nebulock_organization_id
ORDER BY event_count DESC
LIMIT 100;
```

**Validation Rules:**
- ✅ Time bound: 30-day window (reduces scan volume)
- ✅ LIMIT: 100 (count-first strategy, expect low hit rate)
- ✅ Early filtering: WHERE clause before aggregation
- ⚠️ Contains OR clauses - may be expensive but necessary for comprehensive detection

**Interpretation:**
- `oneview_host_count = 0` across all customers → No HPE OneView deployments, close hunt as N/A
- `oneview_host_count > 0` → Proceed to targeted hunt on identified organizations

#### Query 2: HPE OneView Shell Spawning (Post-Exploitation)

**Purpose:** Detect HPE OneView processes spawning interactive shells (strong RCE indicator)

```sql
-- HPE OneView Shell Spawning Detection
-- Purpose: Identify OneView processes spawning shells (T1059.001, T1059.004)
-- Expected: 0 events (highly anomalous)
-- Bound: 30-day window, LIMIT 100

SELECT
    time,
    nebulock_organization_id,
    endpoint.name as hostname,
    endpoint.os.type,
    process.file.parent_name as parent_process,
    process.file.name as child_process,
    process.cmd_line as command_line,
    actor.user.name as user
FROM nocsf_unified_events
WHERE
    time >= now() - INTERVAL 30 DAY
    -- OneView parent processes (Linux)
    AND (
        process.file.parent_name IN ('hpe-oneview', 'oneview-service', 'java')
        OR process.parent.file.path LIKE '%/opt/hpe/oneview/%'
    )
```

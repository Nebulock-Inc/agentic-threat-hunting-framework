### Hypothesis Statement

Adversaries abuse VMware (govc, vim-cmd, esxcli), storage (3parcli, ssmc), and BMC management tools (hponcfg, ilorest) from compromised endpoints, jump servers, or automation platforms to gain privileged access to data center infrastructure. Unlike legitimate automation workflows, malicious execution exhibits unusual parent processes (bash, powershell from non-admin contexts), unexpected source hosts (user workstations vs jump servers), or abnormal execution frequency.

### Threat Context

Enterprise data centers rely on infrastructure management tools for operations:

**VMware vCenter/ESXi management:**
- `govc` - VMware vSphere CLI (VM enumeration, snapshot management, credential access)
- `vim-cmd` - ESXi command-line interface (host configuration, VM control)
- `esxcli` - ESXi system management (network, storage, hardware configuration)
- `vmware-cmd` - Legacy VM management tool

**HPE 3PAR/Nimble Storage management:**
- `3parcli` - HPE 3PAR storage array CLI (volume management, credential access)
- `ssmc` - HPE StoreServ Management Console (storage monitoring, configuration)

**iLO/BMC hardware management:**
- `hponcfg` - HPE iLO configuration utility (server hardware management, credential access)
- `ilorest` - HPE iLO RESTful API tool (Redfish API access, BMC control)

**Attack scenarios:**

1. **Compromised admin workstation:** Malware on admin laptop executing VMware tools to enumerate vCenter inventory
2. **Compromised jump server:** Attacker pivoting from jump server to hypervisor layer using legitimate management tools
3. **Compromised automation platform:** Ansible/Terraform/Jenkins server abused for infrastructure access (supply chain attack)
4. **Insider threat:** Malicious admin extracting infrastructure credentials (vCenter passwords, storage API keys, BMC credentials) for sabotage or sale
5. **Lateral movement:** Adversary using compromised host to access BMC/iLO for out-of-band persistence or firmware implants

**Adversary goals:**
- **Enumerate virtual machines and hosts at scale** (T1580 Cloud Infrastructure Discovery)
- **Access infrastructure credential stores** (T1552.001 Credentials in Files)
- **Pivot to hypervisors and storage arrays** (T1078.004 Cloud Accounts)
- **Exfiltrate VM snapshots or storage data** (T1213 Data from Information Repositories)
- **Establish hypervisor-level persistence** (firmware implants, BMC backdoors)

#### Query 1: Infrastructure Tool Discovery (Count-First)

**Purpose:** Establish baseline frequency of infrastructure tool usage across customer environments

```sql
SELECT
    CASE
        WHEN `process.name` IN ('govc', 'vim-cmd', 'esxcli', 'vmware-cmd', 'esxcfg-info') THEN 'VMware Tools'
        WHEN `process.name` IN ('3parcli', 'ssmc') OR `process.name` LIKE '%3par%' THEN '3PAR Storage Tools'
        WHEN `process.name` IN ('hponcfg', 'ilorest') THEN 'iLO/BMC Tools'
        ELSE 'Other Infrastructure Tools'
    END as tool_category,
    `process.name` as tool_name,
    COUNT(DISTINCT `nebulock_organization_id`) as customer_count,
    COUNT(DISTINCT `endpoint.name`) as host_count,
    COUNT(*) as execution_count
FROM nocsf_unified_events
WHERE
    `time` >= now() - INTERVAL 7 DAY
    AND (
        `process.name` IN ('govc', 'vim-cmd', 'esxcli', 'vmware-cmd', 'esxcfg-info', '3parcli', 'ssmc', 'hponcfg', 'ilorest')
        OR `process.name` LIKE '%3par%'
        OR `process.cmd_line` LIKE '%vcenter%api%'
        OR `process.cmd_line` LIKE '%vsphere%'
        OR `process.cmd_line` LIKE '%3par%api%'
        OR `process.cmd_line` LIKE '%ilo%api%'
        OR `process.cmd_line` LIKE '%redfish%'
    )
GROUP BY tool_category, tool_name
ORDER BY execution_count DESC
LIMIT 100
```

**Validation Rules:**
- ✅ Time bound: 7-day window (discovery phase)
- ✅ LIMIT: 100 (count-first strategy)
- ✅ Early filtering: Tool names and API patterns
- ✅ No SQL comments (MCP-safe)

**Interpretation:**
- `execution_count = 0` → Infrastructure tools not used (expand time window or close hunt as N/A)
- `execution_count > 0` → Proceed to behavioral baseline analysis (Query 2)

## LEARN: Prepare the Hunt

### Hypothesis Statement

Adversaries compromise developer endpoints through malicious npm packages containing supply chain worm code that self-propagates, harvests credentials using Trufflehog secret scanning, exfiltrates stolen data to public GitHub repositories, installs self-hosted GitHub Actions runners for command and control, and destructively deletes home directories as a failsafe. By detecting execution of known malicious artifacts (setup_bun.js, bun_environment.js), Trufflehog tool usage from npm context, Bun runtime evasion techniques, GitHub repository operations, and destructive commands following package installation, we can identify Shai-Hulud 2.0 worm infections before attackers achieve credential theft and data exfiltration objectives.

### Threat Context

**Primary Threat: Shai-Hulud 2.0 npm Worm (November 2025)**

The Shai-Hulud 2.0 worm represents a sophisticated self-propagating supply chain attack targeting the npm ecosystem. Key characteristics from Datadog Security Labs intelligence:

**Nebulock's Response Timeline:**
- **September 2025:** Nebulock conducted initial Shai-Hulud threat hunt (analyst: Eric Brown)
  - Analyzed 90 days of telemetry (2025-09-03 to 2025-09-18)
  - Result: Zero malicious activity detected
  - Action: Recommended systemic defenses (package mirrors, quarantine windows, lockfile requirements, CI/CD reviews)
  - **Key Point:** Hunt completed *before* November 2025 campaign peak
- **November 24, 2025:** Shai-Hulud 2.0 campaign publicly disclosed (Datadog Security Labs)
- **December 2025 (This Hunt):** Follow-up investigation with automated detection implementation
  - Analyzed 30 days of telemetry (2025-11-01 to 2025-12-01)
  - Result: Continued zero malicious activity detected
  - Action: Implemented 2 Sigma detection rules for continuous monitoring
  - Customer deliverable: H-0002-CUSTOMER.md (all-customer report)

**Attack Mechanics:**
- **Self-Propagation:** Backdoors legitimate npm packages by injecting malicious lifecycle scripts (preinstall, postinstall)
- **Credential Harvesting:** Uses Trufflehog open-source tool to scan for secrets in local files and git history
- **Evasion:** Executes payloads using Bun runtime instead of Node.js to evade traditional detection
- **Exfiltration:** Creates public GitHub repositories with programmatically generated names to exfiltrate stolen credentials
- **Command & Control:** Installs self-hosted GitHub Actions runners for persistent access
- **Destructive Fallback:** Deletes entire user home directory if credential exfiltration fails

**Impact Scale:**
- **796 unique npm packages** compromised
- **20+ million weekly downloads** affected
- **500+ GitHub users** compromised
- **Estimated reach:** Thousands of developer workstations globally

**Known Malicious Artifacts:**
- `setup_bun.js` - Primary payload installer (SHA256: `a3894003ad1d293ba96d77881ccd2071446dc3f65f434669b49b3da92421901a`)

## OBSERVE: Expected Behaviors

### What Normal Looks Like

Legitimate npm/Node.js activity on developer workstations:

**Package Installation:**
- `npm install` spawning `node` for package resolution and postinstall script execution
- Node.js executing build scripts: webpack, babel, typescript compilation
- Package managers downloading from registry.npmjs.org, registry.yarnpkg.com
- Postinstall scripts compiling native modules: node-gyp, node-pre-gyp
- Legitimate dependencies downloading platform-specific binaries

**Development Workflows:**
- IDE/editors (VS Code, WebStorm) spawning node processes for language servers
- Node.js running development servers: webpack-dev-server, nodemon, vite
- Test frameworks (jest, mocha, vitest) spawning child processes
- Linters (eslint) and formatters (prettier) executing

**CI/CD Activity:**
- Jenkins/GitHub Actions/GitLab CI runners executing `npm ci` or `npm install`
- Build servers compiling TypeScript, bundling assets with webpack/rollup
- Automated tests running in node environment
- Deployment scripts with git operations (clone, pull, push to deployment repos)

**Baseline Characteristics:**
- npm processes spawn node which may spawn additional node processes
- Network connections to package registries (npmjs.org, yarnpkg.com, jsdelivr.net)
- Postinstall scripts typically compile C/C++ addons (gyp, cmake) or download pre-built binaries
- Parent processes: Terminal, IDE, CI runner, shell

### What Suspicious Looks Like

Indicators of Shai-Hulud 2.0 worm infection:

**Malicious File Execution:**
- Execution of `setup_bun.js` or `bun_environment.js` from any location
- Process command lines containing "Sha1-Hulud" or "Shai-Hulud" strings
- Scripts executing from unusual paths: node_modules/.hooks/, /tmp/, Downloads/

**Trufflehog Abuse:**
- `trufflehog` process execution from npm/node context
- Trufflehog scanning with `filesystem`, `git`, or `github` modes
- Trufflehog invoked during or immediately after package installation

**Bun Runtime Evasion:**
- `bun` process spawned from npm/node/yarn parent processes
- curl/wget downloading from bun.sh domain during package installation
- Bun executing JavaScript files immediately after npm install

**Credential Access:**
- Process command lines referencing credential files: `.npmrc`, `.git-credentials`, `.aws/credentials`, `.config/gh/hosts.yml`, `.ssh/id_rsa`
- Cloud metadata service queries: 169.254.169.254, metadata.google.internal, 100.100.100.200
- Environment variable dumping: `printenv`, `env` executed from npm context
- Git history scanning: `git log --all` from suspicious processes

**GitHub Actions Runner Installation:**
- GitHub Actions runner config.sh execution: `./config.sh --url <repo> --token <PAT>`
- Process command lines containing: "actions/runner", "runner/register"
- Runner installation immediately following npm package installation

**Exfiltration Indicators:**
- `git init` followed by `git remote add` and `git push` in short timeframe (< 5 minutes)
- GitHub repository creation API calls from developer workstations
- Git push to repositories with programmatic names: 18-character alphanumeric patterns `[0-9a-z]{18}`
- Multiple git operations to unfamiliar repositories

**Destructive Indicators:**
- `rm -rf ~` or `rm -rf $HOME` executed from npm/node context
- Bulk home directory deletion: `rm -rf /home/<user>` or `rm -rf /Users/<user>`
- Process parent chain: npm/node → shell → rm with recursive home deletion

### Expected Observables

  - Malicious: `node`, `npm`, `bun`, `trufflehog`, `bash`, `sh`, `curl`, `wget`, `git`
  - Parent chains: `npm → node → setup_bun.js`, `npm → bash → curl https://bun.sh/install`, `node → trufflehog`
- **Network:**
  - Legitimate: registry.npmjs.org, registry.yarnpkg.com

### Hunting Queries

#### Query 1: Malicious File Execution (IOC-Based)

**Objective:** Detect execution of known Shai-Hulud malware files (setup_bun.js, bun_environment.js) and string patterns

```sql
SELECT
    timestamp,
    host_name,
    user_name,
    process_name,
    process_parent_name,
    process_command_line,
    process_executable
FROM nocsf_unified_events
WHERE
    ingest_time >= now() - INTERVAL 14 DAY
    AND (
        process_command_line ILIKE '%setup_bun.js%'
        OR process_command_line ILIKE '%bun_environment.js%'
        OR process_command_line ILIKE '%Sha1-Hulud%'
        OR process_command_line ILIKE '%Shai-Hulud%'
    )
ORDER BY timestamp DESC
LIMIT 500;
```

**Query Notes:**
- Broad IOC search for known malicious file names and string patterns
- No parent process filtering - cast wide net to discover all contexts
- LIMIT 500 to capture substantial dataset without overwhelming analysis
- Will return security research activity as well as actual compromises

**Extended to 30 Days (2025-11-01 to 2025-11-16):**
- Extended period: 13 events (0 True Positives)
- 11 events: Security monitoring scripts running "echo Shai-Hulud Malware not detected!" (legitimate detection validation)
- 2 events: OpenAI Codex tool (rhuber) generating business documents referencing "Shai-hulud npm monitoring" in Autodesk/Cribl research context
- No additional malware executions detected in extended 16-day lookback

#### Detection Rule 1: npm Package Installing Secret Scanning Tools (High Confidence - BEHAVIORAL)

**Behavioral Logic:** Detect package managers spawning credential harvesting tools (Trufflehog, gitleaks, etc.) during or after package installation - indicative of supply chain malware automating credential theft

**ClickHouse Query:**
```sql
SELECT
    timestamp,
    host_name,
    user_name,
    process_name,
    process_command_line,
    process_parent_name
FROM nocsf_unified_events
WHERE
    ingest_time >= now() - INTERVAL 24 HOUR
    AND process_parent_name IN ('npm', 'node', 'yarn', 'pnpm', 'bun')
    AND (
        process_name ILIKE '%trufflehog%'
        OR process_name ILIKE '%gitleaks%'
        OR process_name ILIKE '%detect-secrets%'
        OR process_command_line ILIKE '%trufflehog%'
        OR process_command_line ILIKE '%gitleaks%'
    )
ORDER BY timestamp DESC
LIMIT 100;
```

**Detection Criteria:**
- **Behavior:** Package manager spawning secret scanning tools (Trufflehog, gitleaks, detect-secrets)
- **Context:** npm/node/yarn/pnpm/bun direct parent process
- **TTP:** T1119 (Automated Collection), T1552.001 (Credentials In Files)
- **Why behavioral:** Legitimate developers run secret scanners from shell/IDE, NOT from npm postinstall scripts. This pattern catches ANY malware weaponizing credential scanners, not just Shai-Hulud.

**Validation:** Query 2 executed - 0 true positives (all legitimate security team usage from bash/zsh, none from npm context)

**False Positive Rate:** Very Low (secret scanners from npm context = inherently suspicious behavior)

**Catches:** Shai-Hulud 2.0, future supply chain malware using credential harvesting tools, typosquatting packages with embedded scanners

**MITRE ATT&CK:** T1552.001 (Credentials In Files), T1119 (Automated Collection)

#### Detection Rule 3: Automated Credential File Enumeration from Package Context (Medium Confidence - BEHAVIORAL)

**Behavioral Logic:** Detect package managers spawning processes that enumerate multiple credential file locations - indicative of automated credential harvesting scripts

**ClickHouse Query:**
```sql
WITH credential_access AS (
    SELECT
        timestamp,
        host_name,
        user_name,
        process_parent_name,
        COUNT(DISTINCT CASE
            WHEN process_command_line ILIKE '%.npmrc%' THEN 'npmrc'
            WHEN process_command_line ILIKE '%.git-credentials%' THEN 'git-creds'
            WHEN process_command_line ILIKE '%aws/credentials%' THEN 'aws'
            WHEN process_command_line ILIKE '%.config/gcloud%' THEN 'gcp'
            WHEN process_command_line ILIKE '%hosts.yml%' THEN 'github'
            WHEN process_command_line ILIKE '%.ssh/id_%' THEN 'ssh'
        END) as credential_types_accessed
    FROM nocsf_unified_events
    WHERE
        ingest_time >= now() - INTERVAL 24 HOUR
        AND process_parent_name IN ('npm', 'node', 'yarn', 'pnpm', 'bun')
        AND (
            process_command_line ILIKE '%.npmrc%'
            OR process_command_line ILIKE '%.git-credentials%'
            OR process_command_line ILIKE '%aws/credentials%'
            OR process_command_line ILIKE '%.config/gcloud%'
            OR process_command_line ILIKE '%hosts.yml%'
            OR process_command_line ILIKE '%.ssh/id_%'
        )
        AND process_name NOT IN ('code', 'Code Helper', 'git', 'rsync')
    GROUP BY timestamp, host_name, user_name, process_parent_name
    HAVING credential_types_accessed >= 2
)
SELECT * FROM credential_access
ORDER BY credential_types_accessed DESC, timestamp DESC
LIMIT 100;
```

**Detection Criteria:**
- **Behavior:** Package manager spawning processes that access 2+ different credential file types within same timeframe
- **Context:** npm/node/yarn/pnpm/bun parent process
- **TTP:** T1552.001 (Credentials In Files) with automated enumeration pattern
- **Why behavioral:** Legitimate developers rarely access multiple credential types simultaneously from npm context. This catches the PATTERN (automated multi-credential enumeration) not specific file paths. Malware iterates through credential locations; normal dev tools access one credential at a time.

**Validation:** Query 6 executed - 0 true positives (175 events analyzed, all legitimate single-credential access)

**False Positive Rate:** Low (multi-credential enumeration from npm context is rare in legitimate workflows)

**Catches:** Shai-Hulud's credential harvesting, future supply chain malware with credential enumeration scripts, typosquatting packages with embedded credential stealers

**MITRE ATT&CK:** T1552.001 (Credentials In Files), T1119 (Automated Collection)

    user_name,
    process_name,
    process_command_line,

#### Detection Rule 6: Rapid Git Repository Creation and Data Push from Package Context (Medium Confidence - BEHAVIORAL)

**Behavioral Logic:** Detect package managers performing rapid git repository initialization followed by push operations to external repositories - indicative of automated credential/data exfiltration

**ClickHouse Query:**
```sql
WITH git_operations AS (
    SELECT
        timestamp,
        host_name,
        user_name,
        process_command_line,
        CASE
            WHEN process_command_line ILIKE '%git init%' THEN 'init'
            WHEN process_command_line ILIKE '%remote add%' THEN 'remote_add'
            WHEN process_command_line ILIKE '%git add%' THEN 'add'
            WHEN process_command_line ILIKE '%git commit%' THEN 'commit'
            WHEN process_command_line ILIKE '%git push%' THEN 'push'
        END as git_action
    FROM nocsf_unified_events
    WHERE
        ingest_time >= now() - INTERVAL 24 HOUR
        AND process_name = 'git'
        AND process_parent_name IN ('npm', 'node', 'yarn', 'pnpm', 'bun')
        AND host_name NOT ILIKE '%runner%'
        AND user_name NOT IN ('criblbuild', 'svc-%')
)
SELECT
    host_name,
    user_name,
    MIN(timestamp) as first_operation,
    MAX(timestamp) as last_operation,
    COUNT(DISTINCT git_action) as unique_operations,
    GROUP_CONCAT(DISTINCT git_action) as operations_sequence
FROM git_operations
WHERE timestamp >= now() - INTERVAL 1 HOUR
GROUP BY host_name, user_name
HAVING unique_operations >= 3 AND (MAX(timestamp) - MIN(timestamp)) < 600
ORDER BY unique_operations DESC, first_operation DESC
LIMIT 100;
```

**Detection Criteria:**
- **Behavior:** 3+ distinct git operations (init, remote add, add, commit, push) from same host/user within 10 minutes
- **Context:** npm/node/yarn/pnpm/bun parent process

### Lessons Learned

**What Worked Well:**

1. **IOC-Based Detection (Query 1):** Known malicious file names (setup_bun.js, bun_environment.js) provided immediate, high-confidence detection. String patterns (Sha1-Hulud, Shai-Hulud) successfully captured malware execution.

2. **Progressive Query Refinement:** Query 3 refined 2x to eliminate false positives:
   - Initial: 1000+ container runtime matches (runc, containerd)
   - Refined: 1000+ legitimate Bun development usage
   - Final: 1 false positive (99.9% reduction via parent process filtering)

3. **Parent Process Analysis:** Absence of npm/node parent processes in Query 2 (Trufflehog) confirmed no malicious abuse - all legitimate security scanning from bash/zsh shells.

4. **Time Window Optimization:** Reducing Query 2 from 14-day to 7-day window prevented timeout while maintaining adequate coverage.

5. **Cross-Hunt Reference for Test Data Classification:** Cross-referencing H-0013 identified ec2amaz-lrbf0n1 as internal test environment (Synthetic Data org). This prevented unnecessary investigation of test data and correctly classified detection as IOC validation (Detection True Positive) rather than security threat (Security Threat True Positive).

6. **Progressive Query Refinement (Query 4):** Successfully achieved complete dataset coverage through 5 iterations, reducing from 500+ events (hit limit) to 213 events (full coverage). Key refinement strategies:
   - Removed shell intermediaries (bash/zsh/cmd.exe), kept only npm/node/yarn/pnpm direct parents
   - Targeted high-risk operations only (remote add to external repos, push to origin)
   - Excluded CI/CD infrastructure (gke-k8s-cluster, runner hosts, criblbuild user)
   - Excluded test data operations and IDE read-only commands (ls-tree, ls-files, stash, blame, show)

7. **Count-First Strategy Implementation (Queries 6 & 7):** Applied AGENTS.md Count-First guidance successfully:

   **Query 6 (Credential File Access):**
   - Initial count: 852,665 events (too broad - caught all credential file references)
   - Applied npm/node/yarn/pnpm/bun parent filter
   - Final count: 175 events (manageable dataset)
   - Result: Complete coverage with 100% analysis, no false negatives
   - Validated no Shai-Hulud credential harvesting patterns in npm execution context

   **Query 7 (Cloud Metadata Service Queries):**
   - Initial count: 15,456,909 events (too broad - metadata IPs appear in many contexts)
   - Applied npm/node/yarn/pnpm/bun parent filter
   - Final count: 199 events (manageable dataset)
   - Result: Complete coverage with 100% analysis, identified legitimate cloud environment detection
   - Validated no Shai-Hulud credential theft via metadata service exploitation

8. **Aggregation-First Strategy for Massive Datasets (Query 10):** When COUNT(*) returns millions of events (12.7M), perform aggregation analysis instead of attempting full dataset pull:
   - Initial count: 12,766,674 events (impossible to pull individual records)
   - Strategy: GROUP BY process_parent_name, process_name with COUNT to identify patterns
   - Analysis: Top 100 common chains + bottom 100 rare chains (≤5 occurrences)
   - Result: Established complete baseline of normal process chains without timeout
   - Validated no anomalous chains indicating supply chain compromise
   - Key distinction: Aggregation-first differs from Count-First - used when dataset is so large that even refined queries would hit millions of rows

**What Could Be Improved:**

1. **Query 4 Progressive Refinement:** Required 5 iterations to achieve complete dataset coverage. Initial query too broad - captured all git operations instead of focusing on supply chain attack patterns. Lesson: Start with more restrictive parent process filters (direct npm/node/yarn/pnpm parents only) rather than including shell intermediaries.

2. **False Positive Filtering:** Query 3 initially captured "bundle" substring matches. Future queries should use exact process name matching (`process_name = 'bun'`) instead of wildcards (`ILIKE '%bun%'`).

3. **Host Exclusions:** Added Iago's MacBook exclusion after Query 2 returned excessive legitimate activity. Should proactively identify "noisy" security research hosts earlier.

**Telemetry Gaps Identified:**

1. **Limited Visibility After Malware Execution:** Query 1 detected malware execution on ec2amaz-lrbf0n1, but requires pivot queries to determine if credential theft (Q6), exfiltration (Q4), or destruction (Q8) succeeded. EDR may not capture all post-exploitation artifacts.

2. **Parent Process Context:** Some events missing parent process names (empty fields) - limits ability to determine execution context and legitimacy.

3. **Command Line Detail:** Many events have empty `process_command_line` fields, reducing investigative value for understanding exact tool invocation parameters.

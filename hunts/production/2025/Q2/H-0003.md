## LEARN: Prepare the Hunt

### Hypothesis

**Visibility Gap Pattern:** If endpoint telemetry coverage is incomplete, critical production servers handling sensitive data or internet-facing services will lack process execution, file modification, and network connection visibility, creating detection blind spots that adversaries can exploit via T1562.001 (Impair Defenses: Disable or Modify Tools) by targeting unmonitored assets.

**Why It Matters:** Adversaries actively seek out monitoring gaps during reconnaissance. Unmonitored endpoints represent high-value targets where malicious activity (privilege escalation, lateral movement, data exfiltration) can occur without generating alerts. This hunt validates detection coverage against our asset inventory to identify and close visibility gaps before they are exploited.

### ABLE Framework

**Actor:** N/A — this is a control gap assessment, not threat actor activity

**Behavior:** Expected adversary behavior would be:
1. Reconnaissance to identify unmonitored systems (no EDR, no agent activity)
2. Pivot to unmonitored asset for execution
3. Conduct malicious activity without telemetry generation

**Location:**
- **Production environments:** Database servers, application servers, web servers
- **Data centers:** DC-EAST, DC-WEST, DC-CENTRAL
- **Cloud infrastructure:** AWS EC2, Azure VMs

**Evidence:**
- **Asset Inventory:** Known production servers from CMDB
- **EDR Agent Deployment:** SentinelOne, CrowdStrike, Defender agent lists
- **Telemetry Activity:** Recent process/file/network events per endpoint

### Threat Intelligence

**MITRE ATT&CK Techniques:**
- **T1562.001** — Impair Defenses: Disable or Modify Tools

**Adversary TTPs:**
- **Targeting monitoring gaps:** Adversaries during reconnaissance phase identify systems without security tooling
- **Agent tampering:** Once on a system, attackers disable or uninstall EDR agents to evade detection
- **Pivoting to blind spots:** Lateral movement to unmonitored systems for persistence and command-and-control

**Industry Observations:**
- MITRE ATT&CK Evaluations consistently show detection gaps in environments with incomplete EDR coverage
- Ransomware operators specifically target unmonitored servers for initial encryption staging
- Nation-state actors use monitoring gaps for long-term persistence

## CHECK: Validate and Pivot

### Methodology

**Multi-Phase Approach:**

**Phase 1:** Export asset inventory from CMDB
- Query all production servers (classification: "production")
- Extract: hostname, IP, OS, role, datacenter, owner

**Phase 2:** Cross-reference with EDR agent deployments
- SentinelOne: Export enrolled endpoints
- CrowdStrike: Export sensor list
- Microsoft Defender: Query protected endpoints

**Phase 3:** Identify coverage gaps
- Assets in CMDB but not in any EDR platform
- Assets with stale agent activity (>7 days since last seen)

**Phase 4:** Classify gap severity
- **Critical:** Production servers, internet-facing, handles PII/PCI data
- **High:** Internal production, non-public data
- **Medium:** Development/staging servers
- **Low:** Scheduled for decommission, air-gapped by design

**Phase 5:** Validate with system owners
- Confirm servers are active (not decommissioned)
- Verify no planned agent installation in progress
- Document legitimate exceptions (vendor restrictions, compatibility issues)

**Query 2: EDR Agent Deployment Cross-Reference**

```sql
-- Cross-reference CMDB assets with EDR platforms
WITH cmdb_assets AS (
  SELECT hostname, ip_address, server_role, datacenter
  FROM asset_inventory
  WHERE environment_classification = 'production' AND status = 'active'
),
sentinelone_agents AS (
  SELECT DISTINCT endpoint_name, last_seen
  FROM sentinelone_console
  WHERE agent_status != 'decommissioned'
),
crowdstrike_agents AS (
  SELECT DISTINCT hostname, last_seen
  FROM crowdstrike_falcon_console
  WHERE sensor_status = 'normal'
),
defender_agents AS (
  SELECT DISTINCT device_name, last_activity
  FROM microsoft_defender_console
  WHERE health_status = 'active'
)
-- Identify gaps
SELECT
    ca.hostname,
    ca.ip_address,
    ca.server_role,
    ca.datacenter,
    CASE 
      WHEN sa.endpoint_name IS NOT NULL THEN 'SentinelOne'
      WHEN csa.hostname IS NOT NULL THEN 'CrowdStrike'
      WHEN da.device_name IS NOT NULL THEN 'Defender'
      ELSE 'NO AGENT'
    END as edr_coverage,
    COALESCE(sa.last_seen, csa.last_seen, da.last_activity) as last_agent_activity
FROM cmdb_assets ca
LEFT JOIN sentinelone_agents sa ON ca.hostname = sa.endpoint_name
LEFT JOIN crowdstrike_agents csa ON ca.hostname = csa.hostname
LEFT JOIN defender_agents da ON ca.hostname = da.device_name
WHERE (sa.endpoint_name IS NULL AND csa.hostname IS NULL AND da.device_name IS NULL)
   OR COALESCE(sa.last_seen, csa.last_seen, da.last_activity) < now() - INTERVAL 7 DAYS
ORDER BY ca.datacenter, ca.server_role;
```

**Results:**
- **No EDR agent deployed:** 23 servers
- **Stale agent activity (>7 days):** 8 servers
- **Total coverage gap:** 31 servers (10.8% of production fleet)

**Hosts:**
- `db-postgres-prod-01` (PostgreSQL 14)
- `db-postgres-prod-02` (PostgreSQL 14)

**Validation:**
- Confirmed active with system owners (Database Operations team)
- All handle PII data (customer records, payment information)
- No planned agent installation documented
- Root cause: Vendor compatibility concerns (DBA team concerned about performance impact)

**Risk Assessment:**
- **Visibility Gap:** No process execution, file modification, or network connection telemetry
- **Blind Spots:**
  - Cannot detect SQL injection exploitation → shell execution
  - Cannot detect unauthorized data exfiltration via database tools
  - Cannot detect privilege escalation or lateral movement from DB server
- **Exploitation Scenario:** Attacker compromises web app, pivots to unmonitored DB server, exfiltrates data without detection

**Severity:** **CRITICAL** - High-value targets with sensitive data, zero detection coverage

- 5 servers in DC-CENTRAL: Network isolation issue (firewall rule blocking agent communication)

### Root Cause Analysis

**Why These Gaps Exist:**

1. **Performance Concerns (Perceived)**
   - Database team concerned about EDR agent CPU/memory overhead
   - Web team worried about latency impact on public-facing services
   - **Reality:** Modern EDR agents typically <5% CPU, <200MB RAM

2. **Vendor Compatibility Concerns**
   - Oracle DB team concerned about support implications
   - Some legacy applications lack vendor-tested EDR compatibility

3. **Deployment Process Gaps**
   - No automated agent deployment for new servers
   - Manual installation prone to human error
   - No continuous validation of agent health

4. **Policy Enforcement Gaps**
   - EDR deployment policy exists but not consistently enforced
   - No automated compliance checking
   - Exceptions granted without formal risk acceptance

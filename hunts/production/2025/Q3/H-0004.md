## LEARN: Prepare the Hunt

### Hypothesis

**Exposure Pattern:** If Java4Shell (CVE-2026-114938) is being exploited or creates meaningful exposure in this environment, telemetry should show affected Java versions (17.0.6+/21/25/27) running on internet-facing x86-64 services, and/or a Java process spawning a shell or network tool consistent with post-exploitation.

**Why It Matters:** A newly reported OpenJDK heap-overflow RCE with a CVSS 4.0 score of 9.2 (per public reporting) warrants a rapid exposure check even while the CVE record remains reserved and technical details are unconfirmed, since the primary driver for severity is whether affected versions exist on internet-facing, untrusted-input-handling services rather than developer tooling.

### ABLE Framework

**Actor:** N/A — no threat actor activity identified; this is an exposure assessment, not a known-compromise sweep

**Behavior:** Expected adversary behavior would be:
1. Exploitation of an internet-facing Java service's Base64 decoding path
2. Heap overflow leading to RCE
3. Java process spawning a shell or network/download tool

**Location:**
- **Primary:** macOS developer laptops (SentinelOne, CrowdStrike, Defender telemetry)
- **Secondary:** Windows and Linux endpoints (checked but showed no Java)
- **Gap:** Servers outside EDR coverage not visible

**Evidence:**
- **Process Events:** `process.name` (java/java.exe/javaw.exe), `process.file.path`, `process.command_line`, `parent.process.name`
- **Software Inventory:** Java version records, install paths
- **Architecture:** Homebrew paths, arm64/x86_64 string matches, Rosetta indicators
- **JVM Indicators:** jspawnhelper, IDE launchers, .jar/-Djava. patterns

### Methodology

### Hunt Queries

**Query 1: Java Software and Process Inventory**

```sql
-- Query software inventory and process-creation events for java/java.exe/javaw.exe
-- across all providers and operating systems over 24 hours
SELECT
    endpoint.name,
    endpoint.os.type,
    endpoint.os.architecture,
    process.name,
    process.file.path,
    process.command_line,
    actor.user.name,
    nebulock_provider_name,
    COUNT(*) as execution_count
FROM process_events
WHERE date >= now() - INTERVAL 24 HOURS
  AND (
    process.name IN ('java', 'java.exe', 'javaw.exe')
    OR process.file.path LIKE '%/java'
    OR process.file.path LIKE '%\\java.exe'
    OR process.file.path LIKE '%\\javaw.exe'
  )
GROUP BY endpoint.name, endpoint.os.type, process.name, process.file.path, actor.user.name
ORDER BY execution_count DESC;
```

**Results:**
- **Java process execution found on 10 macOS hosts only** (all via SentinelOne)
- All but one tied to **JetBrains IDE-bundled runtimes** (PyCharm, DataGrip, GoLand)
- **Versions:** Java 21.0.7–21.0.9 and 25.0.3–25.0.4.1
- **One exception:** Temurin 25 JDK install on one MacBook Pro
- **Software inventory:** Nearly empty
  - Returned only unrelated `javascript-common` package on Linux host
  - Apple's `JavaLauncher.app` stub on one CrowdStrike Mac
- **No Java found on any Windows or Linux endpoint**

**Query 2: Internet-Facing Service and Non-Java-Named Launcher Sweep**

```sql
-- Search for named internet-facing Java services and non-java-named
-- processes with JVM-indicative paths or .jar/-Djava. command lines
SELECT
    endpoint.name,
    process.name,
    process.file.path,
    process.command_line,
    parent.process.name
FROM process_events
WHERE date >= now() - INTERVAL 24 HOURS
  AND (
    -- Named internet-facing Java services
    process.name IN ('keycloak', 'jira', 'confluence', 'artifactory', 
                      'jenkins', 'pingfederate', 'kafka', 'solr', 'elasticsearch')
    -- Or JVM-indicative patterns
    OR process.command_line LIKE '%.jar%'

    OR process.file.path LIKE '%/jbr/%'

  )
```

**Query 3: CPU Architecture Classification**

```sql
-- Infer ARM vs x86 status per Java-running host using indirect indicators
WITH java_hosts AS (
  SELECT DISTINCT endpoint.uid, endpoint.name
  FROM process_events
  WHERE date >= now() - INTERVAL 24 HOURS
    AND process.name IN ('java', 'java.exe', 'javaw.exe')
)
SELECT
    jh.endpoint.name,
    -- Check for ARM indicators
    COUNT(CASE WHEN pe.process.file.path LIKE '%/opt/homebrew/%' THEN 1 END) as homebrew_arm_paths,
    COUNT(CASE WHEN pe.process.command_line LIKE '%arm64%' THEN 1 END) as arm64_string_matches,
    COUNT(CASE WHEN pe.process.command_line LIKE '%aarch64%' THEN 1 END) as aarch64_string_matches,
    COUNT(CASE WHEN pe.process.command_line LIKE '%macosx-aarch64%' THEN 1 END) as macosx_aarch64_matches,
    -- Check for x86 indicators
    COUNT(CASE WHEN pe.process.command_line LIKE '%x86_64%' THEN 1 END) as x86_64_string_matches,
    COUNT(CASE WHEN pe.process.file.path LIKE '%/Rosetta/%' THEN 1 END) as rosetta_indicators,
    -- Architecture hint classification
    CASE
      WHEN COUNT(CASE WHEN pe.process.command_line LIKE '%arm64%' OR pe.process.command_line LIKE '%aarch64%' THEN 1 END) > 0
        THEN 'ARM (strong)'
      WHEN COUNT(CASE WHEN pe.process.file.path LIKE '%/opt/homebrew/%' THEN 1 END) > 0
        THEN 'ARM (likely)'
      WHEN COUNT(CASE WHEN pe.process.command_line LIKE '%x86_64%' OR pe.process.file.path LIKE '%/Rosetta/%' THEN 1 END) > 0
        THEN 'x86 (likely)'
      ELSE 'Unknown (weak/mixed hints)'
    END as architecture_classification
FROM java_hosts jh
LEFT JOIN process_events pe ON jh.endpoint.uid = pe.endpoint.uid
WHERE pe.date >= now() - INTERVAL 24 HOURS
GROUP BY jh.endpoint.name
ORDER BY jh.endpoint.name;
```

**Results:**
- **Six hosts** showed **Apple Silicon (ARM) indicators**:
  - Strong indicators: Explicit `macosx-aarch64` path strings
  - Likely indicators: `/opt/homebrew/` paths (ARM-specific Homebrew location)
  
- **Two hosts returned weak or mixed hints:**
  - Could not be conclusively classified as ARM or x86 from telemetry
  - **Manual verification needed:** `uname -m` on these hosts
  
- **Note:** SentinelOne does not populate a CPU architecture field directly

**Vulnerability Exposure Assessment:**
- If ARM hosts are confirmed, they are **potentially not vulnerable** (per hunt brief)
- x86-64 hosts would need further verification of AVX-512 support (not available in telemetry)

**Query 4: Post-Exploitation - Direct Java Parent-Child Hunt**

```sql
-- Search for any process spawned directly by a java/java.exe/javaw.exe parent
```

**Query 5: Post-Exploitation - Broadened JVM-Hosted-Parent Hunt**

```sql
-- Broaden parent definition to IDE launchers, jspawnhelper, JBR/JDK path indicators
-- Search for shell or network-tool children, excluding build/CI/scanning context
SELECT
    endpoint.name,
    parent.process.name,
    parent.process.file.path,
    process.name,
    process.command_line,
    time
FROM process_events
WHERE date >= now() - INTERVAL 24 HOURS
  -- JVM-hosted parent indicators
  AND (
    parent.process.name IN ('java', 'java.exe', 'javaw.exe', 'jspawnhelper')
    OR parent.process.file.path LIKE '%/jbr/%'
    OR parent.process.file.path LIKE '%/jdk/%'
    OR parent.process.file.path LIKE '%/jre/%'
    OR parent.process.file.path LIKE '%PyCharm%'
    OR parent.process.file.path LIKE '%DataGrip%'
    OR parent.process.file.path LIKE '%GoLand%'
  )
  -- Shell or network tool children
  AND process.name IN ('sh', 'bash', 'dash', 'zsh', 'cmd.exe', 'powershell.exe', 
                       'curl', 'wget', 'nc', 'ncat', 'python', 'python3')
  -- Exclude build/CI/scanning context
  AND process.command_line NOT LIKE '%/workspace/%'
  AND process.command_line NOT LIKE '%codeql%'
  AND process.command_line NOT LIKE '%gradle%'
  AND process.command_line NOT LIKE '%maven%'
  AND parent.process.command_line NOT LIKE '%test%'
ORDER BY time DESC
LIMIT 50;
```

**Results:** 18 distinct parent-child combinations found, **all benign IDE or security-tooling behavior:**

1. **PyCharm spawning Python interpreter probes** (multiple hosts)
   - `python3 --version`
   - `python3 -c "import sys; sys._is_gil_enabled()"`
   - Purpose: IDE interpreter detection and GIL-check

2. **PyCharm spawning login shells** (multiple hosts)
   - `zsh`, `bash` with `ij-shell-env-data` environment captures
   - Purpose: IDE shell-environment integration

3. **PyCharm-bundled Codex agent** (one host)
   - Starting a `zsh` snapshot
   - Purpose: AI-assisted coding environment

4. **Microsoft Defender Java scanning** (EC2 Mac host)
   - `lsof -c java -c javaw` running under `bash`/`sh` as root
   - Purpose: Defender's vulnerability assessment

**No curl, wget, nc, ncat, powershell, or cmd.exe child of any JVM-hosted parent was observed**
